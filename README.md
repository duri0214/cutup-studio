# cutup-studio

ローカルの動画・音声素材をコピーせず参照し、手入力の区間メタデータとガイドテキストから、候補を選んで構成 manifest を作る Rust 製デスクトップアプリです。

素材ファイルと区間メタデータはローカルの SQLite カタログで管理します。ローカル LLM、FFmpeg、素材の自動解析・再生はまだ使いません。素材の本体は一切書き出さず、manifest には素材ルートからの相対パスと時間範囲だけを記録します。

操作画面は `vj-copilot` と同じ、ダークテーマとミク色のアクセントを使うライブ操作向けの構成です。候補はカードから選択し、右側の `COMPOSITION STAGE` で確定順を確認します。

## 起動

Rust を導入した状態で次を実行します。

```powershell
cargo run
```

起動直後はカタログ未選択です。`NEW` で素材フォルダを登録するか、`OPEN` で保存済みカタログを開いてください。`DEMO` を明示的に選んだ場合だけ、組み込みデモで候補生成から manifest 保存まで確認できます。デモの参照パスは仮想的なもので、動画・音声の再生や書き出しには使えません。

自身の素材を登録して試す場合は、JSON の手書きは不要です。

1. `01 / MATERIAL CATALOG` の `NEW` を押し、動画・音声が入ったフォルダを選びます。アプリはそのフォルダ内に `material-catalog.sqlite` を作成します。
2. そのフォルダに `material-catalog.sqlite` がすでにある場合は、新規作成を中止します。`OPEN` で既存カタログを開いてください。
3. 走査後に開く「素材と区間の編集」で素材を選び、外部プレイヤーで確認した開始・終了時刻をミリ秒で入力します。
4. 例として、文字起こしに `テッカマン登場`、役割に `導入` を入力して「区間を保存」を押します。役割・タグなどの複数値はカンマで区切ります。
5. 編集ウィンドウを閉じ、GUIDE の導入行に `テッカマン` を入力します。不要な GUIDE 行は削除し、`GENERATE CANDIDATES` を押すと登録した区間が候補になります。
6. 候補を選び、`SAVE MANIFEST` で `composition-manifest.json` を保存します。保存ダイアログは Downloads を初期表示します。
7. アプリを再起動し、`OPEN` で保存した `.sqlite` を選ぶと区間・手動タグが復元され、素材フォルダも再走査されます。

素材を追加・変更・移動・削除した後は `RESCAN` を押します。「素材・区間・タグを編集」では、全文検索とタグ・役割の絞り込み、利用不能・要確認の区間も確認できます。利用不能・要確認の区間は GUIDE の候補から除外します。素材変更後の区間を確認して再保存すれば、同じ ID のまま再利用できます。

フォルダ登録だけでは区間やタグは生成されません。AI 自動解析は後続対応です。拡張子、データ契約、解析結果の保存 API、再走査と検索の詳細は [ローカル素材カタログ](docs/catalog.md) を参照してください。

以前の catalog JSON も `OPEN` のファイル種別を切り替えて読み込めます。この経路は従来の読み取り専用で、SQLite カタログへのインポートではありません。`examples/catalog.json` の `material_root` を実在の素材フォルダへ置き換え、各 `source_path` をその配下からの相対パスにしてください。各区間の形式は次のとおりです。

```json
{
  "id": "segment-id",
  "source_path": "folder/source.mp4",
  "start_ms": 1200,
  "end_ms": 4500,
  "transcript": "文字起こしまたは台詞",
  "keywords": ["語句"],
  "tags": ["画", "音", "反応"],
  "roles": ["導入"],
  "note": "制作上のメモ"
}
```

ガイドは一行につき `役割: 探したい語句 タグ` と書きます。

```text
導入: テッカマン
つなぎ: 驚き 反応
```

候補には元ファイル、開始・終了時刻、根拠、点数が表示されます。各スロットで素材を選び、`MANIFEST を保存` を押すと、選択順・役割・検索語・素材 ID・参照パス・時間範囲・候補根拠を JSON に保存します。

短い自然文 `テッカマンを導入に置き、驚きの反応でつなぐ` も、この最小実証で扱う二つのパターンとして分解できます。再現性を重視する用途では、上記の一行形式を推奨します。

## 構成

`vj-copilot` の Rust 構成をベースに、役割を次のように分けています。

```text
src/
├─ domain/  # カタログ・候補・manifestの値と検索/構成サービス
├─ infra/   # SQLite、素材フォルダ走査、既存 catalog JSON と manifest JSON の入出力
└─ ui/      # eframe画面と VJ 風テーマ
```

リポジトリ運用・Rust・DDD・テストのルールと、Issue／レビュー／ブランチ整理スキルは `.codex/` にあります。
