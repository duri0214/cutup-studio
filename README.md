# cutup-studio

完成済みの動画・音声素材に探す語句・タグ・役割を登録し、GUIDEに沿った構成を作るデスクトップアプリです。素材ファイルはコピーしません。

## 入力と出力

```text
入力: 基準フォルダ（materials/） + 素材に登録した情報 + GUIDE
  ↓
カタログ: material-catalog.sqlite
  ↓
構成: 候補から素材を選ぶ
```

- 基準フォルダの `materials/` に、MP4やWAVなどの素材を入れます。`materials/` は空でも構いません。
- カタログは、素材と探す語句・タグ・役割を次回も使えるように保存します。音声から情報を起こして入力を補助できます。
- 構成レシピの保存・復元と、動画・音声の調理・レンダリングは後続の対応です。

## 起動

Rust を導入してから実行します。

```powershell
cargo run
```

## 使い方

1. 最初に選びます。
   - `NEW`: `materials/` がある基準フォルダを選ぶ。そこに固定名の `material-catalog.sqlite` を作る
   - `OPEN`: 前回使った基準フォルダを選ぶ。固定名の `material-catalog.sqlite` を開く
   - `DEMO`: 同梱素材で試す
2. 素材を走査したら、仮組みとして `素材の情報を登録` で素材に入っている言葉、タグ、役割を保存します。将来はローカルLLMがこの工程を自動化します。素材ファイル1本が、そのまま候補の単位です。
3. GUIDEで役割を選び、`探す語句・タグ` を入力して、表示された候補から素材を選びます。

例:

```text
導入: テッカマン
つなぎ: 驚き 反応
```

## 素材カタログ

素材カタログは、基準フォルダごとの固定名 `material-catalog.sqlite` ファイルです。名前は変更しません。動画や音声ではなく、次の情報を覚えます。

| 種類 | 保存するもの |
| --- | --- |
| 素材 | フォルダ内に現在あるファイル、内容を確かめるための指紋 |
| 素材の情報 | 探す語句、タグ、役割、メモ |

素材を追加・変更・移動・削除した後は、OPENで基準フォルダを開き直します。

- 同じパスの素材内容が変わると、その素材は「要確認」になります。
- 同じ内容の素材を移動・リネームしたときは、移動先が一つだけなら情報を引き継ぎます。
- 素材を削除すると、その素材のカタログ情報も削除されます。
- 要確認の素材は候補に使いません。

アプリが素材をコピーすることはありません。カタログとして開けるのは、このアプリが作成したSQLiteファイルだけです。

この変更より前の「区間」カタログは開けません。古い `material-catalog.sqlite` を別名にしてから、`NEW` で作り直してください。

## いましないこと

- 動画・音声の再生
- 長さ・コーデックの確認
- 文字起こし、タグの自動作成

## DEMO

`DEMO` は `demo/` を基準フォルダとして使います。日本語の合成音声で作った完成済みWAV素材10本を使えます。素材一覧は [demo/README.md](demo/README.md) を参照してください。

## 動画から素材を切り出す

[ローカル AI のセットアップ](src/infra/local_ai/README.md)に従い FFmpeg と whisper.cpp を用意します。YouTube を使う場合は [yt-dlp の公式配布](https://github.com/yt-dlp/yt-dlp#installation)から導入し、`yt-dlp --version` が実行できるよう PATH を設定します。YouTube の取得には yt-dlp 対応の JavaScript 実行環境が別途必要な場合があります。既定以外の場所に置いた場合は、カタログを開き、素材の「設定」で Whisper の実行ファイルとモデルを指定します。音声の言語も同じ設定を使います。

Windows では `winget install --id yt-dlp.yt-dlp --exact --scope user` でも導入できます。インストール後はターミナルとアプリを再起動してください。切り出し画面の信号は各ファイルの検出状態を示し、実際に解析できることまでは保証しません。yt-dlp は YouTube URL の場合に必要です。

01 の「動画から素材を切り出す」で「YouTube URL」を選んで動画ページの URL を入力するか、「ローカル動画」を選んで「ファイルを選ぶ」から手元のファイルを選び、「音声を抽出・文字起こし」を押します。入力元を切り替えると、それまで選んだ動画と候補はクリアされます。URL の音声は一時フォルダに取得し、解析と試聴に使います。一覧の台詞を選んで開始・終了の秒数を調整し、「再生」で確認して「WAVに保存」で保存先を選びます。既存カタログに登録するには基準フォルダの `materials/` に保存し、OPEN で開き直してください。文字起こしの時刻は目安です。再生には Windows では PowerShell、その他の環境では FFmpeg に付属する ffplay が必要です。配信元の動画は変更しません。

## 開発

```powershell
cargo test
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

実装は `src/`、開発ルールは `.codex/` にあります。

### 素材から書き出しまで

1. **01 / MATERIAL CATALOG**: 素材情報を「編集」で手入力・保存できます。「設定」で任意の Whisper と Ollama を選び「音声から情報を起こす」を押すと、文字起こしを探す語句へ、Ollama で抽出したタグ・役割を各欄へ反映します。修正して保存できます。保存後の情報は検索に使われます。
2. **02 / COMPOSITION GUIDE**: 登録した情報を使って候補を探し、素材を選びます。
3. **03 / COMPOSITION**: 選択と順番を保存し、必要に応じて FFmpeg で素材全体を連結して WAV に書き出します。

FFmpeg は 01 の文字起こしと 03 の書き出しの両方で使います。どちらも PATH から自動検出します。Whisper と Ollama は書き出しには不要です。いずれも通常の起動や手入力には不要です。

### 構成の WAV 書き出し

FFmpeg は別途導入します。導入方法は [ローカル AI のセットアップ](src/infra/local_ai/README.md) の FFmpeg の項を参照してください。PATH が通っていれば自動検出します。見つからない場合は導入手順に従って PATH を設定し、アプリを再起動してください。

02 で各素材を選び、03 の「WAVを書き出す」を押して保存先を指定します。画面に表示中の全スロットが対象で、構成の「保存」は書き出しに不要です。未保存の構成があるままアプリを閉じると、保存・破棄・キャンセルを選べます。音声を 48 kHz・ステレオの PCM WAV に変換してファイル単位で順番に連結します。区間指定は未対応です。音声がない素材や壊れた素材はエラーになります。既存の書き出し先は上書きできます。使用中の素材は書き出し先に指定できません。
