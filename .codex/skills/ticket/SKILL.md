# チケット・Issue 作成

- Issue の出力と本文は日本語にする。
- 会話と調査結果から、目的、対応範囲、受け入れ条件、期待される効果を整理する。
- 「issue書いて」「チケット作って」などの依頼は Issue 作成許可として扱い、内容が一意なら確認なしで `gh issue create` まで実行する。
- 「本文だけ」「下書きだけ」と明示された場合だけ、Issue 本文をコードブロックで返し、作成はしない。
- 対象リポジトリが現在の作業ディレクトリと異なる場合は `gh issue create -R <owner>/<repo>` で明示する。

## 本文の形式

```markdown
## 概要

[背景と目的]

## 主な対応内容

- [対応内容]

## 受け入れ条件

- [完了条件]

## 期待される効果

- [効果]
```

## メタ情報

- Assignee は `--assignee @me` で自分に設定する。
- ラベルは対象リポジトリに存在するものだけを使い、判断できない場合は省略する。別リポジトリの `app:` ラベルを持ち込まない。
- `gh project list --owner <owner> --format json` で Project を確認し、追加先が一意なら `--project <title>` で設定する。
- 親 Issue が明示されている、または現在ブランチや open PR から一意に判断できる場合は `--parent` と本文の参照を設定する。候補が複数なら確認する。
- Issue 作成後は URL、Issue 番号、assignee、ラベル、Project、親子関係の設定結果を報告する。

## 確認が必要な場合

- 目的、タイトル、本文を会話から一意に作れない場合
- 親 Issue の候補が複数ある場合
- `gh issue create` やメタ情報設定が失敗した場合
