# UIデザインルール

## 共通部品を使う

- 色、文字色、余白、角丸、文字サイズ、状態色は `src/ui/theme.rs` のトークンを正とする。画面ごとに近い色や寸法を直接増やさない。
- 同じ見た目と操作を2回使うなら、画面内で複製せず `theme.rs` の部品にする。今ある部品はパネル、主操作・通常・危険ボタン、トグル、タブ、入力欄、候補リスト、候補カード、状態バッジ、信号機、アイコンボタンである。
- ボタンの無効表示は `ui.add_enabled_ui` など実際の有効状態から `theme.rs` に委ねる。画面側で、操作可能なボタンを無効風に描画したり、その逆をしたりしない。
- `theme::State` は実際の状態だけに使う。`Selected` は選択済み、`Attention` は再確認が必要、`Error` は処理失敗、`Disabled` は操作不能を表す。見た目のアクセントのために状態を付けない。
- 新しい部品は現在の画面で少なくとも1回使う。将来用の汎用部品は作らない。

## 画面の意味を重複させない

- 一つの画面・タブには一つの主目的を置く。検索条件と保存する属性、実行操作と状態表示を混ぜない。
- タブ名は現在の画面を示す。本文に同じ見出しを重ねない。
- ラベルはユーザーが次にする操作を表す。内部名や抽象名だけで案内しない。
- 次の画面を案内するときは、画面に見える番号と名称を使う。例: `メイン画面の 02 / COMPOSITION GUIDE`。

## 操作状態を正しく見せる

- 選択済み、ON、エラー、保存済みの強調は、実際にその状態になった後だけ表示する。初期値や候補を選択済みに見せない。
- トグルはON/OFFの状態を持つ操作だけに使い、通常の実行ボタンの代用にしない。
- 保存は既定で完了後の次の画面へ戻す。連続操作が必要なときだけ、明示的なチェックボックスで開いたままにできるようにする。
- エラーと次の操作は、問題のある番号のセクションと状態表示の両方で分かるようにする。

## 検索と入力

- 素材の選択は、初期状態で全件を並べず、入力に応じて候補を絞るインクリメンタル検索を基本にする。
- 詳細条件は折りたたみ、主操作を妨げない。
- プレースホルダーは `theme::text_input` を使い、補助色で入力済みの値と区別できるようにする。
- 候補を複数表示する場合は `theme::suggestion_list` と `theme::suggestion_item` を使い、ボタンの羅列ではなくリストとして見せる。候補自体は未選択として描画し、要確認の候補だけを実際の状態で表示する。

## 目検とPR

- UIを変えたら、PRの目検手順を画面上の正確なラベル、入力値、操作、期待結果に更新する。
- 既存の `[x]` は戻さない。新しい未実施確認は別の `[ ]` として追加する。
