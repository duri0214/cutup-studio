# Rust テスト規約

テスト名と構成から、何を保証しているか分かるテストを書く。

## シナリオ

- テスト名には、対象の振る舞いと条件を含める。
- Arrange（前提）、Act（実行）、Assert（検証）の順に構成する。
- コメントは、テスト名やコードだけでは分からない業務上の理由がある場合に限って補う。
- 成功、境界値、失敗、状態遷移のうち、変更に関係するケースを確認する。

## テストの置き場所

- 小さな単位の振る舞いは、対象モジュール内の `#[cfg(test)]` に置く。
- 複数モジュールの連携や公開 API は、`tests/` の統合テストで確認する。
- 非同期テストは、リポジトリで既に使っているランタイムのテスト属性を使う。
- 実時間、ネットワーク、外部サービスに依存するテストは、必要な境界を差し替えられる構成にする。

## 検証

- テストは実装詳細ではなく、利用者から見える振る舞いを検証する。
- `Result` の成功だけでなく、想定するエラーの種類と値も確認する。
- テスト追加後は、対象に応じて `cargo fmt --check`、`cargo test`、`cargo clippy` を実行する。
